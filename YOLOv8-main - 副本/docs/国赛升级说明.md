# 智能交通检测系统 - 国赛升级说明

本轮升级不改变项目题目，目标是把原来的演示程序提升为可答辩、可复现、可继续训练的比赛作品。

## 已完成升级

1. 跟踪逻辑升级
   - 原逻辑主要按中心点距离匹配，容易 ID 跳变。
   - 现改为 IOU 优先、中心距离兜底，并限制不同类别互抢 ID。

2. 速度估计可信化
   - 原报告中曾出现 800 km/h、1100 km/h 等异常速度。
   - 现加入最高可信速度阈值、速度跳变阈值和平滑窗口。
   - 报告会记录“过滤异常速度次数”，便于答辩说明算法边界。

3. 预警事件去重
   - 原逻辑逐帧刷屏，同一风险可重复几十次。
   - 现加入事件冷却时间，同一 ID 同类风险不会短时间重复计数。

4. 报告可信度增强
   - 统计字段改为“最大同帧车辆数/行人数/路障数”，避免把瞬时数量误写为总流量。
   - 报告增加模型路径、焦距、像素尺度、限速阈值、事件冷却时间等参数。

5. 工程可复现性增强
   - 修复 `比赛启动.bat` 中文乱码和错误文件名。
   - 补齐 `requirements.txt`。
   - 新增 `configs/traffic_config.json` 统一管理模型、阈值和类别。
   - 新增训练脚本 `scripts/train_traffic.py` 和评估脚本 `scripts/evaluate_traffic.py`。
   - 新增 `datasets/traffic/data.yaml` 作为自建数据集入口。

6. 演示指标增强
   - UI 增加累计车辆、累计行人、累计路障和实时 FPS。
   - 视频画面左上角增加中文实时演示数据条，便于录制参赛演示视频。
   - 目标框标签改为 PIL 字体绘制，修复 OpenCV 中文显示成问号的问题。
   - 目标框标签显示中文类别，并显示中/高风险等级。
   - 报告增加平均车速、处理帧数和实时处理 FPS。

7. 停车速度抖动抑制
   - 目标中心点加入平滑处理，降低检测框抖动对车速估算的影响。
   - 速度估计加入位移死区和静止速度阈值，停车车辆不会因为轻微框抖动显示明显速度。
   - 默认要求配置 `camera.meters_per_pixel` 后才显示 km/h；未标定时显示“速度待标定”，避免把框抖动包装成真实测速。
   - 连续低位移目标会进入静止锁定，速度强制归零。
   - 新增 AI 光流运动分析：通过前后帧光流和背景运动补偿，把车辆判定为静止、缓行、行驶、快速，并输出 0-100 的 AI 速度指数。
   - 未做真实尺度标定时，系统展示 AI 运动状态和速度指数；完成尺度标定后再展示 km/h。
   - 新增本车主体状态估计：通过背景特征点和全局光流判断录制车辆/摄像机是否静止、行驶、转向或颠簸，再用主体运动补偿目标运动状态。
   - 车载视频中，系统不再单纯看检测框位移，而是先估计本车运动，再判断前方车辆是否相对运动。

8. 摄像头实时输入
   - 新增“实时摄像头”按钮，可直接打开默认摄像头进行实时识别预测。
   - 摄像头检测同样支持目标跟踪、估速、风险预警、截图、视频保存和报告生成。
   - 摄像头编号和采集分辨率由 `configs/traffic_config.json` 的 `input` 字段配置。

9. 智能过滤与道路区域约束
   - 新增道路 ROI 过滤，只保留道路区域内的目标，降低树木、建筑、天空区域误检。
   - 新增类别置信度阈值，交通灯、停车标志等容易误检的类别默认要求更高置信度。
   - 新增最小检测框面积过滤，减少远处小噪声框。
   - 新增稳定目标确认，目标连续出现指定帧数后才进入展示、统计和预警。

10. 行人横穿风险评估
   - 新增可配置横穿风险区域，默认以粉色半透明区域展示。
   - 结合行人是否进入横穿区域、横向运动幅度、附近车辆距离、车辆/本车运动状态，输出低/中/高风险。
   - 中/高风险会在目标标签、右侧统计、预警日志和检测报告中体现。
   - 该模块可作为“面向车载视角的行人横穿风险预警”比赛亮点。

11. 行人视角避险模式
   - 新增“行人端危险来车识别”能力，适用于行人手持手机、佩戴摄像头或移动端视角。
   - 系统不要求画面里出现行人，而是假设摄像头主体就是行人本人，判断前方车辆是否构成威胁。
   - 结合车辆在行人前方危险区的位置、画面占比、接近趋势、AI 速度指数和来车方向，输出中/高风险。
   - 对危险来车给出方向性避险建议：左侧来车向右避让，右侧来车向左避让，正前方来车暂停观察或后退。
   - 该模块可作为“面向弱势交通参与者的 AI 主动避险辅助”比赛亮点。

## 下一轮必须补齐

1. 自建交通数据集
   - 每类建议不少于 300-500 个有效标注框。
   - 场景至少包含白天、夜晚、雨天、拥堵、遮挡、行人横穿、路障占道。
   - 所有素材需确认来源合法，人物车牌尽量脱敏。

2. 训练专用模型
   - 当前默认仍使用 `yolov8n.pt`，这是演示基线。
   - 完成数据集后运行：

```bash
python scripts/train_traffic.py --data datasets/traffic/data.yaml --model yolov8n.pt --epochs 80 --imgsz 640
```

训练完成后，把 `configs/traffic_config.json` 中的 `model_path` 改为：

```json
"model_path": "runs/traffic/yolov8n_traffic/weights/best.pt"
```

3. 输出评估指标

```bash
python scripts/evaluate_traffic.py --weights runs/traffic/yolov8n_traffic/weights/best.pt
```

答辩材料中至少展示：
   - Precision
   - Recall
   - mAP50
   - mAP50-95
   - FPS
   - 与原始 `yolov8n.pt` 的对比

4. 速度标定
   - 如果有固定摄像头，建议测量道路中一段真实距离，配置 `meters_per_pixel`。
   - 没有标定前，只能把车速称为“估算速度”，不能宣传为真实测速。

5. 演示视频规范
   - 使用 1080p、3-5 分钟、无水印、无剪辑的一镜到底演示。
   - 不建议使用带录屏水印或外部字幕的视频作为国赛材料。

## 答辩建议表述

本项目不是简单套用 YOLO，而是在道路交通场景下完成了检测、跟踪、估速、风险预警和报告生成的闭环。当前版本已经具备稳定演示能力，后续通过自建交通数据集训练专用模型，并用检测指标、速度误差和 FPS 证明系统效果。
